# Kuwait Training Needs Survey 2026/27

Arabic (RTL) field survey "استبانة دراسة التموضع التنافسي والاحتياجات التدريبية في الكويت 2026/2027" with smart branching (B2B / B2C paths), autosave/resume, and a protected analyst dashboard that aggregates results and matches field demand against the ASDC Training Catalogue (70 workshops) from the desk study.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — API server (Express, `/api/*`)
- `pnpm --filter @workspace/survey run dev` — survey web app (Vite, preview path `/`; `/admin` is the dashboard)
- `pnpm run typecheck` — full typecheck; `pnpm --filter @workspace/api-spec run codegen` after editing `lib/api-spec/openapi.yaml`
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` (managed), `ADMIN_ACCESS_KEY` (secret; shared research-team key for `/admin` — sent as `Authorization: Bearer <key>` or `X-Admin-Key`). Without it every admin endpoint returns 503.
- `pnpm --filter @workspace/survey run pdf` (add `-- --preview` for PNG page previews in `/tmp/questionnaire-pdf`) — regenerates the printable questionnaire `exports/kuwait-training-needs-questionnaire-2026-2027.pdf` from `survey-definition.ts` via headless system Chromium (`CHROMIUM_BIN` overrides the binary). Generator lives in `artifacts/survey/tools/questionnaire-pdf/` (plain Node type-stripping: relative imports need `.ts` extensions, no TS-only runtime syntax). Pages are fixed A4 boxes; the build fails on overflow, so re-run after changing question wording/options and fix the page plan in `pages.ts` if it fails. The print edition numbers questions 1–19 continuously (both paths visible), unlike the per-path numbering online.

## Structure

- `SURVEY_SPEC.md` — authoritative question text, branching rules, data model and matching framework (from the questionnaire + desk study). `attached_assets/extracted/` holds the extracted desk-study and catalogue text.
- `artifacts/survey/src/lib/survey-definition.ts` — frontend question definitions (ids, Arabic labels, options, groups). Stable ids: skills S1–S10, courses C1–C70 (groups G1–G6), tracks T1–T6. C1–C23 retain the original survey choices; C24–C70 add the remaining workshops from catalogue pages 4–29.
- `artifacts/api-server/src/data/survey-items.ts` — server-side labels + item → catalogue workshop mapping; `data/catalogue.ts` — 70 workshops extracted from the catalogue PDF (approximate figures where the PDF text was ambiguous).
- `artifacts/api-server/src/lib/analytics.ts` — summary, drop-off, skills gap (importance vs performance), course need index (mean of 0/1/2 ÷ 2 × 100), track Borda scores, preferences, matching engine (4-cell grid + composite 40/30/20/10 with ±10 sensitivity), CSV export.
- `lib/db/src/schema/responses.ts` — single `responses` table; all answers live in the `answers` JSONB keyed by question id. Aggregates are computed in Node from JSONB (no derived tables).
- Admin dashboard (`artifacts/survey/src/pages/admin.tsx` shell + `src/components/admin/*` one file per tab, `shared.tsx`/`charts.tsx` primitives). Twelve "chapters", each framed by a research question from `src/lib/study-context.ts` (desk-study constants: 82 reports, 430 programmes, 34-workshop shortlist, 5 trends — study facts, not survey data). Tabs: overview (study pipeline, KPIs, G/P/S/I stakeholder split, duration histogram, booking funnel), infographics (`infographics.tsx` + `infographic-workshops.tsx` on the `infographic-kit.tsx` shell: four glassmorphism poster pages modelled on the client's reference image — page 1 ring + 4 callouts, top-4 skill-gap icon bars, two mini line charts, nested bars of the top-3 workshops per domain G1–G6, six tag cards + timeline; page 2 top-10 workshop leaderboard table joined with catalogue days/tier/evidence, intent-mix stacked bars and a domain summary table; page 3 field-need vs desk-evidence dumbbell chart, three donuts and three workshop fact cards from the matching report (always all respondents, needWeight 40); page 4 track podium + rank distribution, delivery-format tiles, auto-written four-point takeaways. Palette sampled from the ASDC logo, gold #D0A734 / silver #A1A29D over the blurred backdrop `public/infographic-backdrop.jpg`; pages 1, 2 and 4 honour the B2B/B2C filter. Course → workshop joins use `MatchingItem.primaryItems`, the survey items whose primary catalogue link is that workshop), pathways, course-insight and focus-groups (see below), skills (IPA matrix, weighted-gap ranking, B2B−B2C divergence), courses, tracks, prefs (programme profile + B2B-vs-B2C comparison), segments (`GET /api/admin/segments`: per-slice indicators across path/stakeholder/sector/orgSize/nationality/gender/age/jobLevel/education), matching, responses. Segments with fewer than 5 respondents are faded and tagged «للاستئناس»; no significance tests (voluntary sample). Only the six current tracks (G1–G6) are ranked; answers to the retired T1–T6 list are shown separately on record.
- Training pathway board («لوحة المسارات التدريبية», chapter 3) uses `GET /api/admin/training-pathways?path=B2B|B2C` and `src/components/admin/training-pathways.tsx`. All six survey domains remain visible, including empty ones; each has up to three workshops with actual current/future interest. Rankings use need index, book-now share, rating count, then stable course ID. Each workshop's delivery preferences use only its interested respondents (Q25=1 or 2), with per-question denominators, all tied leaders, and low-n warnings. These are general preferences of that cohort, not causal reasons for demand. Catalogue details use the primary course link and are explicitly provisional. Backend logic and in-memory regression tests are in `artifacts/api-server/src/lib/training-pathways.ts` and `tests/training-pathways.test.ts`; they do not alter response records.
- Single-course infographic («الوضع للدورة», chapter 4) lets the admin choose a domain, then any of its workshops (all 70 remain available, not just ranked leaders). `GET /api/admin/course-insight?courseId=C1&path=B2B|B2C` supplies the workshop-specific cohort profile, declared demand, competition rank within evaluated domain courses (exact metric ties share a rank), and B2B/B2C counts inside the chosen scope. Unobserved courses have no rank or path need index; measured zero interest is a distinct state. Insights and programme-design suggestions are derived from survey aggregates, not an external AI service or a promise of bookings. The same cohort-preference and provisional-catalogue rules as the pathway board apply. New logic is in `artifacts/api-server/src/lib/course-insight.ts`, covered by in-memory tests; no survey records are changed.

- Qualitative analysis («التحليل النوعي», chapter 5) uses protected `GET /api/admin/focus-groups` and the generated client hook. The curated report lives only in `artifacts/api-server/src/data/focus-groups/`; it neither queries nor changes survey responses and makes no runtime AI calls. `focus-groups.tsx` and `focus-groups-evidence.tsx` render the executive brief, coverage graph, group matrix, searchable course families, organizational issues, contrasting views, proposed actions and source dialogs. CSV and print are scoped to this report. `tests/focus-groups.test.ts` checks the contract, coverage, links and every exact quote against its original Markdown line range; run these tests from the workspace root.

## Answer shape (answers JSONB)

Q1–Q4, Q6–Q9, Q19–Q23 → option id string · Q5 → `{ sector, sub, other }` · Q10, Q11, Q15, Q26 → option id array · Q14/Q18 → `{ S1: { importance, performance }, … }` · Q24 → ordered track id array · Q25G → selected course-group id array (G1–G6, the "المسارات التدريبية" gate) · Q25 → `{ C1: 0|1|2, … }` (0 غير مهتم, 1 مهتم مستقبلاً, 2 أرغب بالحجز فوراً) **only for courses in the selected groups** — the client prunes answers when a group is deselected.

## Conventions

- Display numbering is sequential per path; original question ids (which skip Q12/13/16/17) are kept internally.
- Never treat not-shown or dropped-off responses as "no need" — course rates use only respondents who saw the course (i.e. whose Q25 contains it). Track-selection shares (`groups` in the course-demand report) use only respondents who answered Q25G.
- Keep the six survey tracks and original course ids/wording stable when expanding the catalogue, to avoid reinterpreting historical responses. Assign new workshops by topic rather than copying the PDF's category structure (e.g. HR analytics belongs under HR). Every catalogue workshop now has a primary course link; legacy secondary links remain for interpretation.
- Participant navigation advances after single answers or fully rated matrix rows. Multi-select, ranking and free-text follow-ups require confirmation so choices are not cut short. Before opening optional contact, validate all required sections and mark the survey complete. Optional contact is a separate contact-only update; leaving or skipping that section must never lose the submitted response.
- Keep the questionnaire's navy-and-gold identity and restrained transitions. Mobile skill ratings show one skill at a time with review navigation and neutral explanations. Course selection must have equal-detail expandable descriptions, no recommended/popular badges, and no preselected ratings.
- In “فجوة المهارات لفرق العمل”, selecting ratings must not advance or scroll automatically on any screen size; mobile users click Next between skills and Continue after all ratings, desktop users use the section navigation.
- In “فجوة المهارات الشخصية”, selecting ratings must not advance or scroll automatically on web or mobile; users click Next between skills and Continue after all ratings.
- Q10 (الحلول المؤسسية) and Q15 (برامج الشباب والجاهزية المهنية) are retired from the active survey and print edition; exclude them from validation, progress and numbering, preserving submitted historical answers.
- Use English digits (0–9) throughout the questionnaire, including ratings, progress, and results; preserve Arabic text and RTL layout.
- Terminology: the questionnaire is always «استبانة» (never «استبيان») in all Arabic copy — UI, admin, metadata, exports and the printed PDF.
- Personalized summaries appear only after submission and never require contact details. They summarize self-reported answers, not validated assessments. Course descriptions are introductory explanations, not promises of verified syllabi or qualifications.
- Required-survey progress excludes optional contact and follows the active branch. Show “saved” only after the server confirms the latest answers; draft autosave and section navigation share one serialized writer.
- After the server confirms a new submission, request `https://health.acs-kw.com/api/c` in a hidden, eagerly loaded iframe while showing optional contact. Keep the same frame mounted through contact and thank-you to avoid a second automatic registration request. Saving contact or Skip shows thank-you without redirect; retain a manual registration link as fallback. Do not request on failed submission or append response/contact data. The user confirmed opening the URL alone registers a response; cross-origin frame/cookie restrictions mean this app cannot confirm remote registration.
